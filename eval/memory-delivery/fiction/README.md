# 《候潮旅社》续写对照

同一份虚构前情和任务在本机 DSH `0.2.2-rc.3` 用 DeepSeek Flash 运行，每组 90 秒。`fixture.json` 内的历史发言及计分项在调用前冻结。启用记忆的两组分别预装同一组已确认摘录。新任务和前情文件均未给出改订的路线、原定的结尾和审读版的声音例外。

四项严格检查覆盖交付文件、改订路线、文件末尾的已确定文字、审读版的声音字样。声音用自然改写时，报告另记语义结果。正文叙事结束处和整个交付文件的结尾分别判断。两条判定对附加的审读备注可能得出不同结果。

## 复跑

1. 把上级目录的 `compare.py`、`native-run.mjs`、`prepare-arm.mjs` 和 `seed-memory.mjs` 复制到新的临时目录。把本目录 `fixture.json` 的 `cases` 以 UTF-8 单独保存为该临时目录的 `cases.json`。
2. 在临时目录运行 `compare.py stage`，指定所需发布包、候选包和候选包哈希。只把每条 `matrix.json` 中的 `arm` 和 `prompt` 送给 `native-run.mjs`。固定 `90000` 毫秒，真实模型凭据走工具的标准输入。
3. 用 `python3 -B score-fiction.py /path/to/staged-case` 读取隔离目录并评分。输出含模型请求次数、作品文件检查和读写轨迹摘要。评分只保留散列及指标，原稿和模型轨迹留在各自的隔离目录。

本实验覆盖预置来源记录后的应用与交付复核。首次每种条件运行一次，迭代四仅复跑候选组。历史自动提取和文学质量均不在本次评估范围。
