# 在新会话接着改同一版 Markdown 稿

两个版本都在项目里时，可以把作者采用的版本和章节绑定到一条项目记忆。比如「第七章渡口用 V2，结尾沿用 V1」。下一个会话查到这条决定后，可以打开当时确认的章节，核对文件是否还是同一版。

1. 把稿件放在项目目录下，用 `## 第七章 渡口` 这样的 Markdown 标题标出要绑定的章节。相同标题在这份文件里应当唯一。
2. 在项目根目录运行下面的命令。用 SoloPup 安装目录或源码目录里的 `scripts/reference-markdown.mjs`。

   ```sh
   node /path/to/solopup-memory/scripts/reference-markdown.mjs '稿件/雨桥 V2.md' '第七章 渡口' V2
   ```

3. 命令输出一行 `确认采用 MarkdownRef: …`。把它作为一条独立消息发给项目里的普通 DSH 会话。让 DSH 用 `memory_write` 记为项目决定，并完整保留从 `MarkdownRef:` 开始的那一行在详情里。只有写入成功或待审条目正式采纳后，才能回查这条决定。
4. 换会话后让 DSH 找到该决定，并用 `memory_document` 按 `recordId` 回查。带有适用条件的决定需要传入当前情境。章节较长时，沿 `nextCursor` 继续读同一章。

每次最多返回 8 KiB 正文。回查会读取并校验不超过 4 MiB 的原始 Markdown 文件，正文按章节分段进入会话。如果稿件被修改、移走，或作者撤回采用，回查会给出状态。需要采用新文件时，可以重新生成一条确认并更新原来的项目决定。只有这条确认绑定的章节参与回查，项目文件本身继续保存在原处。
