# 用两版假稿试一遍隔天续写和交付核对

我是 SoloPup Memory 的维护者。如果你已经在用 DeepSeek Harness，欢迎帮我试一个长项目里容易出错的场景。

1. 新建一个测试项目，写两份虚构的 Markdown 稿。记下「第七章用第一版」，再明确更正「第七章改用第二版，保留原结尾，交付时附修改说明」。用 `memory_search` 查当前约定和来源。
2. 在同一工作区开新会话，让助手交付第七章。打开结果文件，核对主体、结尾和修改说明。旧稿以及当前明确约定带来的例外都能用来对照。
3. 想测压缩，可以在原对话执行 `/compact` 后再做一次。撤回更正后核对它是否退出当前记忆。若有漏项，带上 DSH 版本、插件版本、测试步骤和虚构交付文件反馈。

插件按 MIT 许可发布。配置的模型服务可能收费。反馈时请用虚构材料，保留自己的项目原稿和聊天记录。
