# Can a saved DSH decision make it into the final files?

I maintain SoloPup Memory, a text-memory plugin for DeepSeek Harness. In an earlier cattrs comparison, the model received both the old and updated changelog instructions with memory enabled, yet left the changelog out. A run without memory included the changelog and missed other functionality. Both had a strict score of 0. That result made the delivered files part of the memory test. [Prior beta evaluation and comparison](../runs/2026-11-18-memory-delivery.md)

Version 0.26 puts a short, source-linked set of applicable decisions and preferences into the active request. Conditions and exceptions stay attached. After a successful edit, the DSH `agent/turn-stopping` event can give the assistant one additional step to review the agreed deliverables within the original task. This runs during normal turn closure on supported hosts. [DSH turn lifecycle](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.md#agentturn-stopping--serial)

For the writing case, save a draft choice with an exception, then use a compacted or fresh session to resume the work. Check the original source, the rule available to the assistant, and the resulting files. Withdraw the update and check that it stops appearing in active memory. The benchmark report gives the tested version, model, cases, scoring, and observed failures. [Historical evaluation and reproduction](../runs/2026-11-18-memory-delivery.md) · [DSH compaction](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/compaction.md) · [Dream Review research](../research/dreaming-in-dsh/README.en.md)

If you build against DSH's session log, fork SoloPup or download a versioned source archive, then send a reproduction or a patch for the case you care about. Cases where the right rule reached the assistant and the final artifact still went wrong are especially useful.
