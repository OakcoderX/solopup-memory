# 0.25 长项目回读验收

2026 年 11 月 14 日至 15 日 · SoloPup Memory 0.25.0-beta.1 候选

**这轮要确认的是，DSH 在压缩、重启或历史文件超限后，SoloPup 还能引用作者实际确认的改动和例外。** 样本使用虚构小说《雾港来信》。作者只确认第七章采用 V2，结尾照旧。压缩生成的检查点故意写成 V3。用同一试验分别跑 0.24 已发布包和 0.25 候选包。

## 发布前对照

基线为 npm 公开的 `0.24.0-beta.2`，归档 SHA-256 为 `869c0d879a738056c5cd8557ed7e54e69950b781124d1ba2301a12942211499f`。探测用公开包读写真实 DSH 事件日志，调用宿主自带的压缩，以固定文本替代压缩模型，再退出并启动新的宿主进程。候选在桌面 DSH `0.2.2-rc.1` 和分别安装的官方 DSH `0.2.1-rc.5`、`0.2.2-rc.3` 上复验。

| 场景 | 0.24 基线 | 0.25 候选 |
| --- | --- | --- |
| 原始短消息，重启后回查 | 找回 V2 和结尾例外 | 找回同一原句 |
| 累计压缩一次或两次，重启后回查 | 原话仍存，旧版将它判为已替换 | 找回带结尾例外的 V2 原句 |
| 作者的显式更正单独放在长消息最后一段 | 读不到末段 | 找回完整更正段 |
| 大于 256 KiB 的保存会话，已预存相关更正 | 超上限，跳过 | 复用可验证的小索引，跳过整段历史查询 |
| 大于 256 KiB 的保存会话，缺少索引 | 超上限，跳过 | 请求原话仍标为证据不足 |
| 实际编辑替换、跨项目、撤回 | 拒绝采用 | 拒绝采用 |

候选另做了大日志的索引反例。撤回该来源后，索引中的旧片段不能进入证据。修改同一份持久化日志后，宿主修订标识改变，旧索引失效。这两个反例都没有调用整段历史查询。

## 安装包回查完整流程

用本机 DSH `0.2.2-rc.1` 安装候选包，在隔离配置中提交长会话，再等作者更正所在轮次完全结束。插件保存修订标识和来源片段，之后退出 DSH 并启动新进程。回查时的保存日志为 **668,624 字节**。检查结果显示修订标识吻合、原会话未恢复、没有调用整段历史读取。等待闲置后，普通做梦发出一条 2,012 字节的请求，含作者的更正。随后在同项目的另一会话打开报告，工具重新核对原话，正式记忆数据未变化。

Super Agent 单独做双模式烟测。普通模式 → Super Agent → 普通模式连续完成三份报告。两个切换都等当前任务完成，卸载实验执行器后再次切换会被拒绝。该烟测验证模式切换和隔离，未重复超限案例的报告生成。

## 复跑与释放条件

用项目脚本直接比较归档。测试记录宿主版本、归档 SHA-256、日志大小和整段历史查询次数。后台整理由宿主执行，测试输入和摘要固定，公开对照可离线重现。

```bash
node scripts/probe-long-history.mjs --tgz /absolute/path/to/solopup-memory-0.24.0-beta.2.tgz
node scripts/probe-long-history.mjs --tgz /absolute/path/to/solopup-memory-0.25.0-beta.1.tgz
node scripts/probe-package.mjs --report /absolute/path/to/packaged-acceptance.json
node scripts/soak-dream.mjs --long-cold --tgz /absolute/path/to/solopup-memory-0.25.0-beta.1.tgz
```

发布工作流还会运行 Linux 与 macOS 源码测试、DSH 兼容检查、归档完整性验证和 npm 下载读回。每份验收回执用于它标出的归档 SHA，发布归档以对应 CI 回执和 npm 下载校验为准。0.25 的结论限于已测试的来源回查和流程行为。本试验未调用在线模型衡量摘要质量，也未衡量小说续写的文学质量。
