# SoloPup Memory 0.27 实施与验收

2026 年 11 月 25 日 · 开发候选

## 目标

用户在一个 DSH 项目中改了约定，换会话或恢复任务时能打开准确原话、采用现行约定并保留例外。用户能分别看到记忆是否已保存、上下文是否经过宿主请求核对，以及文件是否读回验证。范围是单人 DSH 文字记忆。

以已发布的 `0.26.0` 为对照，开发副本从 `cbbfd3c` 开始。高推理 GPT-6.2 Sol 子代理负责规划，中推理子代理分别实现前台功能和做梦复核，独立子代理准备宿主复测。

## 实施顺序

| 路径 | 改法 | 通过条件 |
|---|---|---|
| 现行记忆与原话 | 保留已生效约定、历史和原始对话的边界。按记忆记录 ID 经 DSH 会话服务打开绑定的原话。回读前后检查指纹、工作区、修订状态和撤回。 | 小柚改为小栗后能打开更正原话。旧值可按历史查看，同名的另一项目保持独立。来源失效时反馈无法验证。 |
| 本轮回执 | 使用宿主请求校验、实际写入结果和文件核对的观测值。回执只含当前会话内有限的状态、编号和指纹。 | 分清保存与待确认、请求核对与模型采用、读回核对与模型口头确认。文件核对只对读到的那一版负责。 |
| 增量做梦 | 普通执行器和实验 Super Agent 执行器共用队列和预算。优先复核有更正或关联冲突的项目项，已处理且未变化的批次沿用已有去重。重新打开提案时校验版本和证据。 | 来源变化、撤回或用户改口后，带原预览 ID 的复查要求重新审阅。报告只读。用户确认后的写入仍走原有流程，预览 ID 只用于复查。 |

## 验证顺序

1. 先跑原话查找、工作区隔离、修订并发、请求回执、文件指纹和做梦队列的定向程序测试。再跑完整回归、打包检查。
2. 用隔离的原生 DSH 宿主核对实际加载、工具注册和长历史回放。保留稳定版和候选版身份及包指纹。
3. 两个独立项目和三个合成称呼事件检验续接。先用程序化模型作为低成本定位手段，再用真实 Flash 做小样。分别记录实际工具证据、前台输出、成本和边界。复用稳定版已验收的文件交付案例检查回归。
4. 若小样失败，按采集、现行选择、原话回读、请求、执行和文件复核定位。只复测受影响路径。另行记录真实模型、脚本化模型和未覆盖的环境。留待独立验收的范围包括完整做梦收益和 Super Agent 前台恢复。

## 测试基线与判定

原生宿主为 macOS DSH `0.2.2-rc.3`。稳定版 `0.26.0` 和候选版分别在独立 DSH 配置上运行。样本只含合成文本，关闭自动捕获和做梦，验证显式记录、修订、冷会话查找和项目隔离。

| 场景 | 稳定版，脚本化模型 | 候选版，脚本化模型 |
|---|---|---|
| 记录小柚并改为小栗 | 小柚进入历史，小栗为现行约定 | 同样通过。两次保存均有回执。 |
| 新会话询问称呼与出处 | 查到小栗及保存时附带的原话 | 重新打开 DSH 原消息，核对消息编号与指纹。回执的请求摘要包含现行记录 ID。 |
| 切换到另一项目 | 查询不到称呼 | 查询不到，用已知完整记录 ID 也回读不到来源。 |

候选版以 DSH 的包安装与配置补丁两种方式各跑一次，均通过。每次 15 次脚本化请求，0 次远程模型调用。稳定版对照用了 10 次脚本化请求，增加的步骤用于验证新版工具，调用数用于描述测试，不用于推断实际用量变化。

真实 Flash 关闭思考，使用同一隔离配置分两段运行。第一段完成两次写入后触及测试用量护栏，第二段只续跑两个新会话，保留第一次的写入。原项目答「小栗」并逐字引用经核验的更正。另一项目答暂无确认称呼。共 13 次模型请求，输入 13,935 个未缓存 token、38,144 个缓存读取 token，输出 1,500 token。无记忆组和稳定版的同配置真实 Flash 对照留待后续实验。

文件小样在原生 DSH 上通过。插件从磁盘读回 `终稿.md` 并匹配要求。修改末行后，重查得到新的 SHA-256 和 `mismatch`。下一轮可看到前轮分别记录的两次结果。此用例采用脚本化模型。

做梦回归为 82 项通过、6 项可选测试跳过。覆盖旧队列迁移、证据暂不可读时的延后重试、不同项目排队、确认丢失时的零模型调用报告，以及用户后来改口时的过期预览处理。

最终候选包 SHA‑256 为 `1c4da549607de1c2b2b05b6108937b15313e56eb49c2d469084c3d287efd99a9`，已用原生 DSH 重新验证上述称呼工具链路。真实 Flash 和文件小样使用 `cf7fbf2ed772d4d41beb1c6c01c82b2be7586d9378b1ed17ed5dc31f7feea327`。逐文件比较 223 项，两个归档包仅 `test/test-schema.mjs` 不同。该文件已更新以检查两个新增工具的宿主 schema，运行时代码逐字节一致。原始回执和两个包均保存在本地候选验收目录。

最终安装包内的全套测试为 1,159 项通过、6 项可选测试跳过、0 项失败。原生 DSH 的宿主历史契约、长历史冷重启、撤回来源拒绝、从干净配置安装和卸载保留数据均通过。另跑了安全自查与两个机械评测门禁。公开基准本轮未运行。

请求核对只能证明宿主送出的上下文包含该条约定。文件核对只对读回那一版负责。做梦在本轮验证的是排队、证据复查和过期提案拦截。做梦实际改善多少、自动捕获表现和 Super Agent 完整恢复仍需要单独验证。
